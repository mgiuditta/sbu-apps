# La riscrittura sullo stesso bundle migra i dati della versione precedente al primo avvio

Quando un'**App Sbu** in Swift sostituisce una versione già in vendita scritta con un altro stack (la 1.0 Expo di Subscriptions, `sbu_subscriptions.db` in SQLite), al primo avvio legge in sola lettura i dati della versione precedente con le API di sistema (SQLite3, nessuna dipendenza) e li converte in automatico, in silenzio. L'aggiornamento automatico dell'App Store sostituisce la vecchia app prima che l'utente possa esportare, quindi un import solo da CSV o una partenza da zero perderebbero i dati di fatto. Una riga illeggibile si salta senza fermare le altre, e Impostazioni dice quante ne mancano, con "Riprova". Il file vecchio resta intatto almeno per tutta la major nuova, e un flag evita doppioni. Le notifiche già programmate dalla versione precedente si cancellano tutte e si riprogrammano dai dati migrati. Il percorso di aggiornamento si prova con un database di esempio nei test e, prima del rilascio, installando la nuova build sopra quella dello Store su un dispositivo.
